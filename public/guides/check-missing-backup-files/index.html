백업 점검

외장하드 백업에서 빠진 사진 찾기: 파일 개수가 같아도 안심할 수 없는 이유

원본과 백업 폴더의 파일 수가 같아도 사진이 빠졌을 수 있습니다. 여섯 파일 시험으로 빠른 비교와 정밀 비교의 차이를 확인했습니다.

작성·확인 2026년 11월 24일 · KYD · 7분 읽기

핵심 요약
  • 파일 개수와 전체 용량은 빠진 파일을 알려 주지 못합니다.
  • 이름과 크기만 비교하면 내용이 바뀐 파일을 놓칠 수 있습니다.
  • 빠진 목록을 먼저 만들고, 그 파일만 다시 복사하세요.

개수가 같은데 빠져 있을 수 있다

원본이 6개이고 백업도 6개라면 잘 복사된 것처럼 보입니다. 그런데 백업에 예전 파일 하나가 남아 있고 새 동영상 하나가 빠졌다면 개수는 그대로 6개입니다. 아래는 이런 상황을 일부러 만든 시험입니다.

빠른 비교는 b.jpg를 같은 파일로 판단했습니다. 크기가 같았기 때문입니다. 또 c.jpg를 빠진 파일로 보고했지만 실제로는 백업의 다른 폴더에 있었습니다. 정밀 비교는 두 경우를 모두 구분했습니다. 시험 결과 원자료와 시험 코드를 공개합니다.

그렇다고 빠른 비교가 쓸모없지는 않습니다. 수만 개 파일에서 빠진 것을 먼저 추리고, 중요한 폴더만 정밀 비교하면 시간을 아낄 수 있습니다.

내 백업 점검 순서

  1. PC에서 외장하드를 연결하고 복사가 모두 끝났는지 확인합니다.
  2. 폴더 비교 도구에서 원본 폴더와 백업 폴더를 차례로 고릅니다. 두 폴더는 같은 단계의 폴더여야 합니다. 원본에서 '사진'을 골랐다면 백업에서도 '사진'을 고릅니다.
  3. 먼저 빠른 비교로 빠진 파일을 확인합니다.
  4. 가족사진처럼 중요한 폴더는 정밀 비교로 다시 확인합니다.
  5. CSV 목록을 저장하고, 목록에 있는 파일만 다시 복사합니다.
  6. 다시 비교해 남은 항목이 없는지 봅니다.

브라우저가 "파일을 업로드하시겠습니까?"라고 물을 수 있습니다. 폴더를 고를 때 브라우저가 보여 주는 공통 문구이며, 이 도구의 페이지는 외부로 파일을 보낼 수 없도록 보안 정책으로 막아 두었습니다.

이 비교로 알 수 없는 것

  • 사진이 정상적으로 열리는지는 알 수 없습니다. 원본이 이미 깨져 있으면 똑같이 깨진 사본도 "같음"입니다.
  • 외장하드의 수명이나 고장 여부는 검사하지 않습니다.
  • 클라우드에만 있고 PC에 내려받지 않은 파일은 읽지 못하거나 선택할 때 내려받아질 수 있습니다.
  • 백업이 한 곳뿐이라면 비교 결과가 완벽해도 그 장치가 고장 나면 끝입니다. 동기화와 백업의 차이도 확인하세요.

자주 묻는 질문

숨김 파일도 비교하나요?

브라우저가 넘겨준 파일만 비교합니다. Thumbs.db, desktop.ini, .DS_Store처럼 시스템이 자동으로 만드는 파일은 결과를 어지럽히므로 제외합니다. 빈 폴더는 파일이 없어 비교 대상이 아닙니다.

한글 파일 이름이 맥과 윈도우에서 다르게 처리되지 않나요?

맥에서 만든 한글 이름은 자음과 모음이 나뉘어 저장될 때가 있습니다. 도구는 이름을 같은 방식으로 맞춘 뒤 비교하므로, 눈에 같은 이름이면 같은 경로로 봅니다.

휴대폰에서도 되나요?

폴더를 통째로 고르는 기능은 PC 브라우저에서 가장 안정적입니다. 휴대폰 사진은 먼저 PC로 복사한 뒤 비교하세요.

정밀 비교가 너무 오래 걸립니다

모든 바이트를 읽으므로 외장하드 속도만큼 시간이 걸립니다. 연도별 폴더로 나누어 실행하고, 절전 모드가 켜지지 않게 하세요. 중단해도 원본과 백업은 바뀌지 않습니다.

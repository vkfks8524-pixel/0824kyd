파일 확인

복사한 사진이 원본과 같은지 확인하는 방법

눈으로 같아 보이는 사진과 내용까지 같은 파일은 다릅니다. 다섯 가지 시험 파일로 차이를 확인하고 결과별로 할 일을 정리했습니다.

작성·확인 2026년 11월 24일 · KYD · 5분 읽기

핵심 요약
  • 용량이 같아도 내용이 다를 수 있습니다.
  • 내용이 다르다고 모두 손상된 것은 아닙니다.
  • 내용이 같아도 사진이 열리는지는 따로 확인해야 합니다.
목차
  1. 두 가지 질문을 나눠야 한다
  2. 다섯 쌍으로 확인한 결과
  3. 내 사진으로 확인하기
  4. 윈도우 기본 기능으로 확인하기
  5. 자주 묻는 질문

두 가지 질문을 나눠야 한다

복사가 잘 됐는지 확인하려면 질문을 둘로 나눕니다. 첫째, 두 파일의 내용이 완전히 같은가. 둘째, 그 파일이 실제로 열리는가. 첫 번째 질문에 "예"라고 해서 두 번째도 "예"는 아닙니다. 원본이 이미 깨져 있으면 사본도 똑같이 깨져 있기 때문입니다.

다섯 쌍으로 확인한 결과

KYD가 만든 작은 그림 파일로 시험했습니다. 카메라 사진이 아니라 원리를 확인하기 위한 파일입니다.

비교바이트 수결과알 수 있는 것
이름만 바꾼 사본458 / 458같음이름은 내용과 관계없음
정보 한 글자만 변경458 / 458다름보이는 그림은 같아도 파일은 다름
색 하나만 변경458 / 458다름용량이 같다고 같은 파일은 아님
앞부분만 남은 파일458 / 200다름복사가 끊긴 경우
깨진 파일끼리200 / 200같음같아도 열리지 않을 수 있음

시험 파일은 목록에서 내려받아 직접 비교할 수 있습니다.

내 사진으로 확인하기

  1. 원본과 사본을 준비합니다. 메신저로 받은 사진은 압축됐을 수 있어 같은 파일이 아닙니다.
  2. 두 파일 비교에서 각각 고르고 비교합니다.
  3. 같다고 나오면 사본을 열어 봅니다.
  4. 다르다고 나오면 아래 표에서 원인을 찾습니다.
차이흔한 원인다음 행동
사본이 훨씬 작음메신저·메일 압축, 크기 줄임원본 전송 방법으로 다시 받기
사본이 조금 다름위치정보 삭제, 회전, 앱의 정보 추가편집한 기억이 있는지 확인
크기는 같고 내용이 다름정보 수정, 드물게 저장장치 오류한 번 더 복사해 다시 비교
사본이 0바이트복사가 시작만 되고 실패다시 복사

윈도우 기본 기능으로 확인하기

웹사이트를 쓰지 않고 확인하려면 PowerShell의 해시 명령을 쓸 수 있습니다. 두 파일의 결과가 같으면 내용이 같습니다.

Get-FileHash -Algorithm SHA256 -LiteralPath "D:\사진\a.jpg"

여러 파일이라면 폴더 비교가 편합니다.

자주 묻는 질문

여러 번 복사하면 사진이 흐려지나요?

파일을 복사하는 것만으로는 바뀌지 않습니다. 흐려지는 것은 앱이 다시 압축해 저장하거나 메신저가 줄여서 보낼 때입니다. 복사와 다시 저장은 다른 동작입니다.

날짜와 이름이 다른데 같다고 나옵니다

파일 이름과 파일 날짜는 내용 바깥의 정보라 비교하지 않습니다. 내용이 같다면 나중에 찾기 편한 이름을 쓰면 됩니다.

해시값이 같으면 사진이 안전한가요?

내용이 같다는 뜻이지, 사진이 정상이거나 원본이 믿을 만하다는 뜻은 아닙니다. 이미 깨진 파일을 복사해도 해시값은 같습니다. 마지막에는 반드시 열어 보세요.

언제 비교하는 것이 좋나요?

원본을 지우기 전, 외장하드를 바꿀 때, 오래 보관한 하드에서 다시 꺼낼 때가 중요합니다. 특히 원본을 지운 뒤에는 비교할 기준이 없으므로, 확인은 지우기 전에 끝내야 합니다. 비교 결과와 날짜를 메모해 두면 다음 점검 때 무엇을 이미 확인했는지 알 수 있습니다.

클라우드에 올렸다가 다시 받은 사진도 비교할 수 있나요?

비교할 수 있습니다. 같다고 나오면 그 사진은 원본 그대로 돌아온 것입니다. 다르다고 나오면 저장용량을 아끼는 화질로 올렸거나 서비스가 정보를 덧붙였을 수 있습니다. 사진과 동영상을 하나씩 시험하면 내 계정의 백업 설정이 원본을 보존하는지 직접 확인할 수 있습니다.

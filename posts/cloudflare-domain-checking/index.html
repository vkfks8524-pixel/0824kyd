Cloudflare Pages domain still pending? Check DNS and certificates separately

By KYD Editorial · First published 2026-07-12 · Last editorial review 2026-10-05

English edition adapted on 2026-10-05. The original source-check date is retained below; this is not a fresh product or match investigation.

A pending domain can involve DNS delegation, the Pages custom-domain association or certificate validation. Identify which stage is incomplete instead of repeatedly deleting and recreating the same settings.

Verify nameserver delegation where required

For a Cloudflare-managed zone, compare the nameservers configured at the registrar with the exact pair assigned by Cloudflare. Old or misspelled entries can prevent the expected delegation. Nameserver requirements differ for a root domain and a subdomain using an external DNS provider; use the official custom-domain instructions for your setup rather than applying one method to every host.

Add the domain inside the Pages project

Creating a DNS record is not the same as registering a custom domain with Pages. Inspect the project’s Custom domains screen and its validation status. Compare the target with the intended production deployment. A working pages.dev URL helps distinguish a file-deployment problem from a custom-domain problem; it does not establish that DNS and HTTPS are ready.

Nameservers still point to the previous providerRegistrar delegation and Cloudflare’s assigned pairRepeated changes during propagation

Root and www are different hosts

kyd.kr and www.kyd.kr require separate checks. If both are used, configure the appropriate associations and choose one canonical destination. One can be active while the other remains pending. Test the already-active address before changing it to troubleshoot the other.

Check DNSSEC and record conflicts

If the setup remains pending, compare DNS records and dashboard errors. When changing DNS providers, stale DNSSEC delegation information, including a registrar’s DS record, can cause validation failures. Review the provider’s instructions before altering security settings. Preserve mail and unrelated service records; changing nameservers is not permission to delete them.

Waiting is a checkpoint, not a diagnosis

DNS caches and certificate issuance can take time. A short wait immediately after a change is not by itself proof of failure. The original guide used a next-day check as a practical reminder, not a guaranteed 24-hour completion deadline. Record what changed and inspect current DNS responses and certificate errors instead of restarting configuration repeatedly.

Prepare useful support evidence

Provide the hostname, registrar delegation, expected DNS target, Pages status, check time and exact error. Keep account IDs and API tokens out of screenshots. If files work on pages.dev but not on the custom domain, say so; that narrows the investigation without claiming that every Pages setting is correct.

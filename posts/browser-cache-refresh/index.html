브라우저 문제 해결

웹페이지가 수정됐는데 예전 화면이 계속 보일 때 해결 방법

작성: KYD 디지털 가이드 편집팀 · 게시 2026년 7월 12일 · 최종 검토 2026년 9월 6일

수정한 화면이 보이지 않을 때는 브라우저, 배포된 파일, 접속 주소를 나눠 확인해야 합니다. 캐시를 지우기 전에 어떤 증거를 비교할지 정하면 로그인 정보나 저장된 데이터를 불필요하게 지우는 일을 줄일 수 있습니다.

증상 비교 · 개발자 도구 확인 · KYD 사례

먼저 같은 주소와 같은 내용을 비교하세요

주소 표시줄의 전체 URL을 복사해 비교합니다. www 유무, 경로, 로그인 계정, 언어 설정이 다르면 화면도 달라질 수 있습니다. “화면이 다르다”는 인상 대신 새로 수정한 문장 한 줄이나 버튼 이름 하나를 비교 대상으로 정하세요.

관찰 결과에서 다음 점검으로 넘어가기
관찰다음 점검아직 확정할 수 없는 것
일반 창만 예전 화면캐시, 확장 기능, 로그인별 콘텐츠, 서비스 워커 확인시크릿 창이 다르다는 사실만으로 캐시 오류 확정
다른 기기에서도 예전 문장배포 커밋·출력 폴더·도메인 연결 확인모든 요청이 같은 CDN 캐시를 통과했는지 여부
문장은 새것, 색·간격은 예전 것HTML이 참조하는 CSS URL과 응답 내용 확인CSS 캐시인지 선택자 우선순위 문제인지 여부
프리뷰 주소만 새 화면운영 배포 브랜치와 운영 도메인의 대상 확인프리뷰 성공이 운영 배포 성공이라는 결론

새로고침과 데이터 삭제는 구분합니다

Windows의 Chrome·Edge에서 일반 새로고침 뒤 Ctrl + Shift + R로 다시 요청해봅니다. 시크릿 창도 비교에 쓸 수 있지만 로그인과 확장 기능 조건이 달라진다는 점을 기록합니다. 시크릿 창이 CDN이나 서버 캐시까지 비우는 것은 아닙니다.

캐시 삭제가 필요하다면 브라우저의 삭제 대화상자에서 캐시된 이미지 및 파일만 선택했는지 확인합니다. 쿠키·사이트 데이터·저장된 비밀번호는 별개입니다. 특히 웹앱의 오프라인 초안이 있다면 사이트 데이터를 지우기 전에 내보내기나 저장 여부를 확인하세요.

운영자는 Network에서 응답 자체를 봅니다

  1. Chrome·Edge 개발자 도구의 Network 탭을 열고 페이지를 다시 불러옵니다.
  2. 문서 요청을 선택해 Request URL과 Status를 기록합니다. 다른 주소로 리디렉션되었다면 최종 주소도 확인합니다.
  3. Response에서 수정한 문장이 들어 있는지 검색합니다. 응답에는 새 문장이 있는데 화면은 예전 것이라면 클라이언트 렌더링·서비스 워커·로그인별 상태를 더 봅니다.
  4. CSS 요청도 별도로 선택해 파일 URL과 실제 내용이 배포한 파일과 맞는지 확인합니다.
  5. 개발자 도구가 열린 동안만 Disable cache를 켜 비교할 수 있습니다. 비교가 끝나면 원래 설정으로 돌립니다.

304 Not Modified는 재검증 결과 기존 응답을 재사용할 수 있다는 뜻입니다. 오류나 낡은 파일이라는 증거가 아닙니다. 200도 최신 커밋의 파일이라는 보장은 아닙니다. 상태 코드와 함께 실제 본문·파일 버전을 비교해야 합니다.

KYD에서 확인한 실제 주소 중복 사례

2026년 9월 6일 KYD 공개 사이트를 점검했을 때 /와 /public/가 모두 200을 반환하며 같은 제목의 홈페이지를 제공했습니다. /public/posts/windows-file-extension/에서도 원래 글과 같은 콘텐츠가 열렸습니다. 이는 브라우저 캐시 때문이 아니라 배포된 폴더가 두 주소로 노출된 사례입니다.

같은 파일을 루트와 public 폴더에 유지하는 저장소 구조가 원인이었고, 해결은 /public/*를 원래 경로로 보내는 리디렉션을 배포하는 것입니다. 이 사례에서 브라우저 데이터를 지우는 일은 중복 URL을 해결하지 못합니다. 도메인·출력 폴더·대표 주소 점검에서 확인 항목을 이어볼 수 있습니다.

CSS 파일 버전과 쿼리 문자열의 한계

배포할 때 내용 해시가 들어간 파일명(예: style.a1b2.css)을 사용하면 새 HTML이 새 CSS를 요청하도록 만들 수 있습니다. 파일명은 예시입니다. 파일만 바꾸고 HTML 참조를 바꾸지 않으면 적용되지 않습니다.

?v=2 같은 검색 조건을 덧붙이는 방법은 서버·CDN의 캐시 키 설정에 따라 효과가 다릅니다. 강제 우회가 보장되는 기법으로 취급하지 마세요. CDN 캐시 삭제가 필요한 경우 운영자의 공식 대시보드에서 해당 URL 범위를 먼저 검토합니다.

해결됐다고 판단할 증거

운영 도메인에서 수정 문장이 들어 있는 HTML과 의도한 CSS를 받았고, 새 브라우저 세션에서도 같은 내용이 보이면 해결 증거로 남길 수 있습니다. 문의할 때에는 전체 URL, 확인 시각, 기대한 문장, 실제 문장, 배포 커밋을 함께 전달하세요. 로그인 쿠키가 포함될 수 있는 네트워크 기록은 그대로 공개하지 않습니다.

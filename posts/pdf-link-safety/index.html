Is that PDF link safe? Check the URL, filename and links inside

By KYD Editorial · First published 2026-07-12 · Last editorial review 2026-10-05

English edition adapted on 2026-10-05. The original source-check date is retained below; this is not a fresh product or match investigation.

A “view PDF” message presents three separate questions: where the link goes, what file you receive and where links inside the document lead. Passing one check does not settle the next.

Message link → downloaded file → document link

  1. Message link: text such as form.pdf may point somewhere else. On a computer, inspect the hover destination; on a phone, use an address-copy feature if the app provides one. Some previews connect immediately, so use another contact method when the message is suspicious.
  2. Downloaded file: inspect the end of its full name. form.pdf.exe is an executable name with .pdf in the middle. Even an actual .pdf extension does not verify file contents.
  3. Link inside the document: a signature button can lead to a separate site. Check the new destination again if it asks for login, payment or installation.

Read these example URLs without opening them

These are educational strings, not reports of real attacks or clickable destinations. The host identifies the server; a path or query value does not replace it.

Example stringHostWhat remains unknown
https://docs.example.com/form.pdfdocs.example.comThe response format and sender’s authenticity
https://example.com@files.example.org/form.pdffiles.example.orgThe text before @ is not the destination host
https://files.example.org/example.com/form.pdffiles.example.orgThe institution-like text is only in the path
https://files.example.org/?document=form.pdffiles.example.orgA query value ending in .pdf does not guarantee a PDF response

Use the local URL structure checker to compare the hosts without visiting them. An @ in a path or query is different from the user-information separator before the host.

A login request is not automatically fake

Restricted Drive or business documents can legitimately require login. Confirm that you expected the document, recognize the service and have the correct address. Open the service independently or ask the sender to verify the invited account and permissions.

SituationActionDo not assume
An expected document has a permission errorAsk the sender to check your account and roleThat the error itself proves phishing
Viewing requires a new app or certificateStop and confirm through an established official contactThat a logo verifies the installation
The PDF is password protectedConfirm the file and password channel independentlyThat encryption proves either danger or safety
The browser blocks the downloadRequest an official original or alternative documentThat a structural URL check overrides a security warning

If you already acted

Record separately when you saw the message, opened the link, downloaded or executed a file, and entered information. Do not include the password or verification code itself in a report. Follow the action-based response guide. For work documents, use the responsible team instead of uploading confidential files to a public scanning service.

Know the limit of basic checks

A matching host and extension are clues, not malware certification. HTTPS protects a connection; it does not establish the document author’s identity. Do not forward a suspicious file to friends to see whether it opens. The September 6 revision separated these three stages and distinguished normal access controls from warning signs.

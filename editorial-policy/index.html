편집 원칙

독자가 확인하고 바로잡을 수 있는 글을 만듭니다

KYD 디지털 가이드는 작성 주체, 확인한 근거, 검토일과 수정 창구를 글 안에서 확인할 수 있도록 운영합니다.

1. 주제 선정

초보자가 실제로 자주 막히고, 잘못 누르면 개인정보 노출이나 데이터 손실로 이어질 수 있는 디지털 생활 문제를 우선합니다. 단순 검색어 나열, 다른 글의 요약, 다운로드만 유도하는 페이지는 만들지 않습니다.

2. 자료 확인

기능을 만든 회사의 도움말, 제품 문서, 정부·공공기관의 보안 안내처럼 책임 주체가 분명한 1차 자료를 우선합니다. 각 글의 “공식 자료와 확인 기준”에 실제로 참고한 주소와 최종 확인일을 표시합니다. 공식 설명으로 확인할 수 없는 개인 경험을 일반적인 사실처럼 쓰지 않습니다.

3. 작성 방식

  • 증상, 원인 구분, 안전한 확인 순서, 중단해야 할 신호를 함께 설명합니다.
  • 삭제·초기화·권한 변경처럼 되돌리기 어려운 작업은 백업과 결과를 먼저 알립니다.
  • 운영체제와 앱 버전별 차이가 있으면 메뉴 이름이 달라질 수 있음을 밝힙니다.
  • 제조사 공식 고객지원, 법률·의료·금융 전문가의 개별 판단을 대신하지 않습니다.

4. 작성자와 검토일

현재 글은 개인 실명이나 확인되지 않은 경력을 내세우지 않고 “KYD 디지털 가이드 편집팀” 명의로 발행합니다. 모든 정보 글에 최초 게시일과 최종 검토일을 표시합니다. 날짜만 새롭게 보이도록 바꾸지 않으며, 출처 또는 본문을 실제로 다시 확인했을 때 검토일을 갱신합니다.

5. 오류 수정

오류 제보가 들어오면 해당 글, 제보 내용, 공식 원문을 대조합니다. 독자의 안전이나 핵심 절차에 영향을 주는 오류는 우선 수정하고 최종 검토일을 갱신합니다. 표현 개선처럼 의미가 달라지지 않는 편집은 별도 공지 없이 반영할 수 있습니다.

6. 기능형 도구의 설계와 검토

도구는 기존 글에서 설명한 판단을 직접 확인하도록 돕는 경우에만 만듭니다. 사용자의 비밀번호·인증번호·개인 파일을 요구하지 않고 가능한 계산은 브라우저 안에서 처리합니다. 자동 결과를 안전 보증처럼 표현하지 않으며 사용법, 결과 해석, 한계와 공식 근거를 함께 공개합니다. 도구 허브와 결과 중심 화면에는 광고 코드를 배치하지 않습니다.

7. 광고와 편집 독립성

광고는 콘텐츠 작성과 분리합니다. 광고주가 글의 결론, 추천 순서, 링크를 결정하지 않으며 광고를 메뉴·다운로드 버튼·본문 링크처럼 보이게 배치하지 않습니다. 광고보다 본문과 탐색 기능을 먼저 사용할 수 있는 구조를 유지합니다.

8. 생성형 도구 사용

초안 정리나 문장 검토에 자동화 도구를 사용할 수 있지만, 공개 전에는 편집 주체가 출처, 링크, 위험 안내와 문맥을 확인합니다. 자동 생성된 내용을 검토 없이 대량 게시하거나 존재하지 않는 경험·통계·전문 자격을 만들지 않습니다.

9. 제보 방법

문의와 오류 제보 페이지에서 공개 GitHub 이슈로 알려주세요. 공개 창구에는 개인정보, 비밀번호, 인증 코드, 결제 정보가 포함된 내용을 올리면 안 됩니다.
